- Canon review for usage point identity: `bounded-consumers` still describes the writer's deadline and shutdown behaviour. No quality covers event point identity: distinct event identities should keep separate points, subject to the accepted hash collisions, and redelivery should replace itself. Flagged for the operator; the canon was not edited.
- Usage point identity was run against a real InfluxDB 2.7, with one consumer and with three on one queue: every event was stored, redelivery replaced itself, and all consumers computed the same offsets. The Go tests use a fake that reproduces InfluxDB's replace-on-same-identity rule; a fake that only records requests would pass with the defect present.
- `usagePointTime` must never change once released. An event written under one function and redelivered under another becomes two points and is counted twice.
- Known and not fixed here: two consumers enforcing for the same account at the same moment each find no journal entry and each write one, so a warning action can run twice. It was reproduced on `main` with three consumers and predates this work. Corrected totals mean more accounts cross, so it will show more often.
