## Stage 3 of `--basic-auth-file` and handoff

- Agent fixtures that assert while holding `a.mu` deadlock the cleanup `Shutdown` on failure, because `require` exits the goroutine with the lock held. A fault check showed this as a ten-minute hang instead of a failure. Copy the fields out under the lock and assert after unlocking.
- Fault checks run for the stage, each caught by its fixture: the agent ignoring the reference; resolved users written onto the saved request; the file read once and cached; the CLI's file-capability check removed; the agent logging the prepared request; the `InvalidArgument` classification removed; the CLI dropping the path from the request.
- A UTF-16 credentials file is not always refused. Its bytes still contain `:` (0x3A), so the first line parses as a garbled user, and the file is refused only when its last line is a lone NUL (a trailing newline). Either way no share is created without authentication. The boundary is documented in `docs/current/agent-share-lifecycle.md`.
- Canon drift found reading `terminus-canon/projects/zrok` against the landed code, for the operator; the canon was not edited:

The landed contract, now in `exitCodesHelp` and the website table, also gives exit 2 to input or conditions the command refuses before the request, and to the agent's `InvalidArgument`.
